# MeteOmo

**「心の空模様」を記録し、医療・福祉・研究・社会参加・国内と海外の医療施設と福祉施設の発展へつなげるためのセルフモニタリングアプリ**

MeteOmo（メテオモ）は、**天気・気圧・気分・服薬・日々の体調や生活上の困りごと**を、できるだけ負担なく記録し、本人が自分自身の変化を振り返るために開発しているアプリケーションです。

名称は **Meteo（気象）** と **Emotion（感情）** を組み合わせたものです。

---

# MeteOmoを考えた理由

MeteOmoの構想は、単に「気分を記録するアプリを作りたい」というところから始まったものではありません。

当初から、

- うつ病などの精神疾患と、天候・気圧・季節・生活状態との関係を継続的に記録できないか
- 本人が服薬状況と気分の変化を同じ時間軸で確認できないか
- 通院時に「最近どうでしたか」と聞かれても上手く説明できない人が、自分の記録を医師へ提示できないか
- 障害年金の申請・更新等で、日常生活上の困りごとや状態の変化を後から整理する負担を減らせないか
- 将来的に、十分な倫理・プライバシー対策と本人の明確な同意を前提として、蓄積された記録を医学・心理学・気象と心身状態の研究に役立てられないか
- さらに長期的には、うつ病を含む精神疾患の治療法・治療薬の研究へ間接的に貢献できる仕組みを作れないか

という問題意識から検討を始めました。

天候や気圧とうつ症状・気分・体調との関係については様々な研究や議論がありますが、MeteOmo自身が、

**「気圧が低いからうつ状態になった」**

**「この天気だから症状が悪化した」**

と因果関係を断定するものではありません。

MeteOmoが行うのは、

**「その時期に、この天候・気圧が記録され、本人はこのような気分・体調・服薬状況を記録していた」**

という事実を、本人が後から確認できる形に整理することです。

そこから先の医学的判断は、医師・研究者その他の専門家が行う領域だと考えています。

---

# 「記録すること」から支援へつなげる

MeteOmoでは、記録そのものを最終目的にはしていません。

目指している流れは、

**記録する**

↓

**自分の状態を知る**

↓

**必要なら医師・福祉職・支援者へ説明する**

↓

**必要な支援へつながる**

というものです。

体調が悪い時、人は必ずしも自分の状態を正確に覚えているとは限りません。

診察室で、

「先月はどうでしたか」

「薬を飲んだ日はどうでしたか」

「眠れなかったのはいつ頃ですか」

「日常生活で何が出来ませんでしたか」

と聞かれても、その場ですべてを思い出すことは難しい場合があります。

そのためMeteOmoでは、本人が日常の中で少しずつ記録し、必要な時にまとめて振り返れる仕組みを重視しています。

# 初期版の基本構成

初期版では、概ね以下の流れで利用する構成を予定しています。

```text
アプリ起動
    ↓
初回案内
    ↓
必要な権限を本人が選択
    ↓
トップ画面
    ├─ 天気・気圧表示
    ├─ 気分記録
    ├─ 服薬確認
    └─ 設定
    ↓
記録
    ├─ 気分詳細
    ├─ タグ
    ├─ メモ
    └─ 服薬
    ↓
振り返り
    ├─ 履歴
    ├─ グラフ
    └─ PDF
```

位置情報や通知等は、アプリを利用するために無条件で許可を要求するのではなく、必要な機能を使用する時点で本人が選択できる構成を目指しています。

---

# 1. 気分記録

トップ画面から、できるだけ少ない操作でその時の気分を記録できるようにします。

基本となるのは、

- 良い
- 普通
- つらい

等のシンプルな段階記録です。

さらに必要に応じて、

- 記録日時
- 気分の詳細
- 任意タグ
- 利用者自身が追加したタグ
- 自由記述メモ

等を追加できます。

同じ日に複数回記録することも想定しています。

「朝は普通だったが、夕方からつらくなった」

といった日内変化も、一日の評価一つだけで潰さず残せるようにします。

---

# 2. 記録を強制しない

MeteOmoでは、毎日欠かさず記録することを利用者へ要求しません。

そのため、

- 連続記録日数による評価
- 達成率による評価
- 未記録日の警告
- 「今日も記録出来ませんでした」といった否定的表示
- 記録を促す過度な通知

は原則として使用しません。

記録出来ないほど体調が悪い日もあります。

その日を、

**「記録を怠った日」**

として評価するのではなく、

**「記録が存在しない日」**

として扱います。

---

# 3. 服薬記録

利用者自身が登録した薬について、

- 薬名
- 予定時刻
- 服薬した時刻
- 服薬した
- 服薬しなかった
- 後で記録する
- 対象外

等を記録できる構成を検討しています。

重要なのは、

**「飲む予定だったこと」と「実際に飲んだこと」を分けて記録すること**

です。

MeteOmoは薬を飲むよう命令したり、飲まなかった利用者を責めたりしません。

また、

- この薬が効いている
- この薬を増やした方がいい
- この薬を止めた方がいい

といった医療判断も行いません。

---

# 4. 天気・気圧等の気象情報

MeteOmoでは、取得可能な気象情報を本人の記録と同じ時間軸で表示します。

想定する情報には、

- 天気
- 気圧
- 気温
- 湿度
- 情報取得時刻

等があります。

重要なのは、**気象情報と本人の入力を別のデータとして扱うこと**です。

例えば、

```text
10:30
気圧：1002 hPa
天候：雨

本人記録
気分：つらい
タグ：頭痛
```

という状態は表示できます。

しかし、

```text
気圧が1002 hPaなので気分が悪化しました
```

とは表示しません。

相関らしき傾向が見えても、原因とは断定しないためです。

---

# 5. 履歴・グラフ

一定期間の、

- 気分
- 服薬
- 天気
- 気圧
- メモ

等を時系列で確認できる履歴・グラフ機能を予定しています。

例えば、

```text
気圧
  ↓
1015 ──────
1010 ───╲──
1005 ─────╲

気分
良い    ●
普通        ●
つらい          ●
```

のように、同期間の複数の記録を視覚的に比較します。

この表示も分析結果ではなく、本人が自分で振り返るための可視化です。

---

# 6. PDF出力

MeteOmoの重要な機能の一つとして、本人の記録を一定期間ごとにPDFとして整理する機能を予定しています。

想定しているPDFには、

- 対象期間
- 作成日
- 任意の表示名
- 記録日数
- 気分カテゴリごとの記録回数
- 服薬記録件数
- 気象データ取得日数
- 日時
- 気分
- タグ
- メモ
- 服薬状態
- 気象情報
- 気分・服薬・気圧等のグラフ
- 注意事項

等を掲載します。

PDFは、

- 本人による振り返り
- 医師への経過説明
- 福祉職・支援者への説明

等に利用することを想定しています。

ファイル名には個人名を初期値として含めず、文書メタデータにも薬名や自由記述等を不用意に埋め込まない設計を検討しています。

---

# 7. 障害年金等に関する記録整理

将来的には、

- 日常生活で困ったこと
- 出来たこと
- 出来なかったこと
- 睡眠
- 外出
- 家事
- 対人活動
- 就労状況
- 体調変化
- 通院状況

等を本人が継続的に記録し、必要な時に整理できる機能を検討しています。

障害年金の申請や更新時には、長期間の生活状況を後から思い出して説明しなければならない場合があります。

MeteOmoは、そのための**本人記録を整理する補助ツール**となることを目指しています。

ただし、

- 障害年金を受給できるか
- 何級になるか
- 申請が通るか
- どのように書けば認定されるか

をMeteOmoが判断することはありません。

虚偽・誇張した記録の生成も行いません。

制度上の判断は、医師、社会保険労務士、行政その他の専門家へ確認することを前提とします。

---

# 8. 医療・福祉への接続

MeteOmoは医療そのものを提供するアプリではありません。

しかし、

**医療や福祉へ説明するための情報を、本人が整理する道具**

にはなれると考えています。

そのため将来的には、

- 医師が確認しやすいPDF
- 支援者へ提示しやすい記録形式
- 公的相談機関への導線
- 地域の相談窓口情報

等を検討します。

MeteOmo上の記録だけを根拠として診断・治療・緊急性を判断することはありません。

---

# 9. プライバシーと本人管理

MeteOmoでは、気分・服薬・自由記述等の非常に個人的な情報を扱います。

そのため、

**「収集出来るから収集する」設計にはしない**

ことを基本方針としています。

初期版では、

- 気分・服薬等を端末内へ保存
- 保存データの保護
- 本人による削除
- 必要な場合のみ外部通信
- 外部通信内容の説明
- 位置情報を拒否しても主要記録機能を利用可能にする
- 不要な利用者追跡を行わない

等を重視しています。

利用者の記録を、企画者等が一覧表示して閲覧するための管理画面を初期版に設ける予定はありません。

---

# 10. PDFやデータ共有も本人操作を基本とする

記録の共有は、本人が必要と判断した時に行うことを基本とします。

PDFを医師へ送る場合も、

**MeteOmoが自動送信するのではなく、本人が内容を確認して共有する**

構成を基本とします。

アプリ外へ共有されたファイルはMeteOmoから削除出来ないため、その点についても利用者へ説明します。

---

# 11. AIは補助であり、主役ではない

初期構想ではAIとの会話や傾向分析も検討していました。

しかし現在のMeteOmoでは、

**AIよりも本人の記録を中心にする**

ことを明確にしています。

将来的にAIを利用する場合も、

- 記録整理
- 振り返り補助
- 情報の要約
- 操作支援

等へ限定し、

- 診断
- 治療判断
- 服薬判断
- 緊急性判断
- 年金認定判断

等を行わせない方針です。

# 研究への貢献

MeteOmoを考えた初期の目的の一つに、

**精神疾患、気象、服薬、生活状態に関する研究へ、利用者本人の意思で協力できる仕組み**

があります。

特に、

- うつ病等の精神疾患
- 天候
- 気圧
- 季節
- 睡眠
- 服薬
- 気分変化
- 日常生活上の状態

等を長期間記録することで、将来的に研究へ利用可能なデータ構造を作れないかと考えています。

最終的には、うつ病等の治療法や治療薬開発の研究へ間接的に貢献できる可能性も視野に入れています。

ただし、この機能を実現する場合でも、

**本人の同意なしにデータを研究利用することはありません。**

研究連携を行う場合には、

- 明示的なオプトイン
- 同意しなくても通常機能を利用可能
- 研究目的の説明
- 提供先の説明
- 提供項目の説明
- データ最小化
- 匿名化・仮名化の検討
- 再識別リスクの評価
- 同意撤回方法
- 法令確認
- 必要な倫理審査
- 研究機関との契約

等を前提とします。

# 気象と心身状態に関する研究

MeteOmoでは、天候・気圧と気分や体調を同じ期間で記録します。

これは、

**気象条件と精神・身体状態の関係を本人が振り返れるようにすること**

が第一目的です。

その蓄積が、将来的に適切な研究設計と本人同意の下で利用可能となれば、

- 気圧変化
- 天候
- 季節
- 気分
- 体調
- 服薬

等の関係を研究するためのデータとして役立つ可能性があります。

MeteOmo自身は研究結果を先取りして因果関係を断定しません。

# 国内外の教育・支援施設への寄付構想

MeteOmoの初期設計では、将来的な社会貢献機能として、本人が希望した場合に、

- 国内の教育機関
- 国内の福祉・支援団体
- 海外の教育施設
- 支援を必要としている地域・団体

等への寄付へつながる仕組みも検討していました。

単なる募金ボタンではなく、

**「自分も誰かの役に立てた」という体験を作ること**

を目的の一つとしています。

病気や障害、社会的困難を抱えている人は、しばしば「支援される側」という役割だけを与えられがちです。

しかし、

**支援を受けている人も、別の誰かを支援する側になれる**

という循環を作ることには意味があると考えています。

MeteOmoでは、

**セルフケア**

と

**社会への小さな貢献**

を完全に別のものとして扱うのではなく、

本人の無理のない範囲で両方を結び付け、

- 自尊心
- 自己効力感
- 社会とのつながり
- 教育支援
- 福祉支援

へつなげられる可能性を検討しています。

寄付を利用条件にしたり、寄付しない人へ罪悪感を与えたりする設計は採用しません。

# 「支援されるだけ」で終わらせない長期構想

MeteOmoの長期構想では、

**体調を記録する**

だけで終わることを目指していません。

例えば、

```text
体調・気分を記録する
        ↓
自分の状態を理解する
        ↓
医師・支援者へ説明する
        ↓
必要な支援を受ける
        ↓
自分に可能な活動量を知る
        ↓
学ぶ・創作する・小さく働く
        ↓
無理のない形で社会参加する
```

という流れを作れないかと考えています。

ここから先を担う別構想が、**Sprout（スプラウト）**です。

# Sproutとの将来連携構想

Sproutは、精神的・身体的・社会的な困難を抱える人が、

**自分のペースで学び、働き、表現し、必要に応じて収入にもつなげる**

ための支援プラットフォーム構想です。

MeteOmoとは別のプロジェクトですが、将来的な連携を想定しています。

MeteOmoが主に、

**「今の自分の状態を知る」**

ためのシステムであるのに対し、

Sproutは、

**「その状態で無理なく何が出来るか」**

へつなげる構想です。

# 目指しているもの

最終的に目指しているのは、

**病気や障害を「克服してから社会へ戻る」ことだけを前提にしない仕組み**

です。

体調が完全に安定していなくても、

- 今日は記録だけする
- 今日は少し勉強する
- 今日は何もしない
- 調子の良い日に少し仕事をする
- 出来る範囲で誰かを助ける

といった選択肢があってよいと考えています。

MeteOmoはその中で、

**「今の自分を把握する場所」**

を担当します。

Sproutは将来的に、

**「その自分のまま、無理なく学び・働き・社会と関わる場所」**

を担当する構想です。

# 開発応援機能

初期版では広告やサブスクリプションを主要な利用条件とせず、希望する利用者だけが任意で利用できる開発応援機能を検討しています。

購入しないことで、

- 機能を大きく制限する
- 何度も購入を要求する
- 心理的な圧力を掛ける
- 「支援してください」等を繰り返す

といった設計は採用しません。

気分記録、服薬記録、気象情報、グラフ、PDF等の基本機能は、応援購入の有無とは分離する方針です。

---

# アクセシビリティ

MeteOmoでは、体調が悪い時でも操作しやすいことを重要視しています。

設計上、

- 文字拡大
- 読み上げ
- 十分なコントラスト
- 色だけに依存しない表示
- 不要な動きを減らす
- 簡潔な文章
- 操作数を少なくする
- エラー時に次の操作を示す
- 通信不能でも記録を可能な限り継続する

等を検討しています。

---

# MeteOmoが行わないこと

MeteOmoは以下を行うためのサービスではありません。

- 病名の推定
- 医療診断
- 重症度の医学的判定
- 治療方法の提案
- 薬の開始・中止・増減指示
- 薬効の医学的判定
- 緊急性・安全性の断定
- 天候と症状の因果関係の断定
- 障害年金の受給可否判定
- 障害年金等級の判定
- 申請結果の保証
- 虚偽・誇張した記録の生成
- 未記録日の状態の推測
- 本人の同意のない研究利用
- 本人の同意のない第三者への健康情報提供
- 心理状態を利用した過度な課金誘導

MeteOmoは、医師、医療機関、福祉専門職、行政その他の専門機関を代替するものではありません。
