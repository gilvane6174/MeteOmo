# MeteOmo Release Criteria

最終更新：2026-08-27\
目的：初期公開版について「実装したから公開」ではなく、公開判断に必要な条件を事前に定義する。

## 1. Release Blocker

以下のいずれかが未解決の場合、初期公開版の公開可とはしない。

### データ

-   [ ] 気分記録が正常に保存・再表示できる
-   [ ] 服薬記録が正常に保存・再表示できる
-   [ ] 編集・削除で意図しないデータ消失が発生しない
-   [ ] 全データ削除が仕様どおり動作する

### 主要機能

-   [ ] 気分記録の主要導線が完了できる
-   [ ] 服薬記録の主要導線が完了できる
-   [ ] 履歴を表示できる
-   [ ] グラフを表示できる
-   [ ] PDFを生成できる
-   [ ] 気象情報取得失敗時にアプリ全体が利用不能にならない

### プライバシー・安全

-   [ ] 外部通信の目的・送信内容の説明と実装が一致している
-   [ ] 位置情報を拒否しても主要記録機能を利用できる
-   [ ] 不要な利用者追跡を行っていない
-   [ ] PDF共有前に本人が内容を確認できる
-   [ ] Privacy Policyと現行実装・現行設計の内容が一致している
-   [ ] 医療・診断・治療・服薬・因果関係を断定する文言がない

### アクセシビリティ

-   [ ] 主要操作のタップ領域を確認
-   [ ] 文字サイズ拡大時に主要操作が破綻しない
-   [ ] VoiceOverで主要導線を操作できる
-   [ ] 色だけで重要な状態を表現していない
-   [ ] グラフ等に代替となる情報提示がある

### 品質

-   [ ] Critical Issueが0件
-   [ ] 未解決High Issueについて公開可否を個別判断済み
-   [ ] 主要導線で再現性の高いクラッシュがない
-   [ ] 対象iOS・対象端末条件を確認済み

### 公開

-   [ ] App Store掲載文と実装内容が一致している
-   [ ] スクリーンショットと現行UIが大きく食い違っていない
-   [ ] 必要な権限説明文を確認済み
-   [ ] 公開前共同確認事項を確認済み

## 2. Non-Blocker

軽微な表示調整等、中心価値・安全・データ・主要操作へ影響しない問題は、Issueとして残した上で公開後対応とすることがある。

## 3. Go / No-Go記録

公開判断時に以下を記録する。

-   判定日：
-   対象ビルド：
-   未解決Critical：
-   未解決High：
-   Privacy確認：
-   Accessibility確認：
-   App Store要件確認：
-   Go / No-Go：
-   判断理由：
-   開発担当確認：
