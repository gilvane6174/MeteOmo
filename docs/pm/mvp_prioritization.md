# MeteOmo MVP Prioritization

最終更新：2026-08-27\
方式：MoSCoWを参考に、初期公開版の中心価値と開発範囲を整理する。

## 判断基準

優先順位は次の観点から判断する。

1.  MeteOmoの中心価値「低負担な記録と振り返り」に必要か
2.  初期公開版として安全・プライバシー上必要か
3.  医師・福祉職等へ本人が説明する用途に寄与するか
4.  初期版でなければ価値が成立しないか
5.  開発・テスト範囲を不必要に拡大しないか

## Must｜初期版の成立に必要

-   気分記録
-   気分詳細・タグ・任意メモ
-   服薬記録
-   天気・気圧等の取得・表示
-   履歴
-   グラフ
-   PDF出力
-   設定
-   データ保存・削除
-   プライバシー説明
-   必要な権限の選択
-   位置情報拒否時にも主要記録機能を利用できる設計
-   主要導線のアクセシビリティ
-   App Store公開に必要な表示・安全要件

## Should｜初期版で重要だが、公開可否は実装状況と受入条件で判断

-   支援情報への導線
-   通知設定
-   開発応援チップ
-   PDFの表示・共有UXの改善
-   グラフのテキスト代替・説明改善

※最終的な初期版採用状態は、現行採用設計図と開発担当との確認を優先する。

## Could｜初期版後に検討可能

-   CSV / JSON等の追加エクスポート形式
-   より詳細な統計・振り返り表示
-   記録カテゴリの追加
-   他サービスとの連携

## Won't for Initial Release｜初期版では実装しない／中心機能にしない

-   AIによる診断・治療・服薬判断
-   AI健康相談
-   PHQ-9 / GAD-7等の健康尺度の本格実装
-   クラウド同期
-   利用者記録を企画者・開発者が閲覧する管理画面
-   研究目的のデータ提供
-   Android / Webの同時公開
-   障害年金の認定可否・等級・申請結果の予測
-   天候・気圧と症状の因果認定

## 優先順位変更ルール

以下の場合は優先順位を再検討する。

-   βテストで主要操作を妨げる問題が判明した
-   データ消失・プライバシー・安全上の問題が判明した
-   App Store審査上の要件変更が発生した
-   技術的制約により当初仕様の実装が困難になった
-   初期版の中心価値をより小さな実装で満たせることが判明した

変更時は `decision_log.md` に理由を記録する。
